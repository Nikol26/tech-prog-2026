Тема работы — автоматизированное тестирование ПО.

В этой лабораторной я написала тесты для игры из предыдущих работ.
Для тестирования использовала Python, pytest и unittest.mock.

## Что я проверяла

| Паттерн | Тестовый класс | Что проверяется |
|---|---|---|
| Singleton | `TestDiceSingleton` | Один экземпляр Dice, диапазон бросков, вероятности 0 и 1, выбор из списка и повторение последовательности при одинаковом seed |
| Prototype | `TestItemPrototype` | Копирование предметов и независимость их зачарований |
| Proxy | `TestCachingHeroRepository` | Загрузка при первом обращении, чтение хранилища один раз, обновление кэша и обработка ошибок |
| Chain of Responsibility | `TestDamageChain`, `TestBarrierHandler` | Порядок обработчиков, уклонение, броня и расход барьера |
| Decorator | `TestEnemyDecorators` | Совместная работа вложенных усилений врага |
| Adapter | `TestHauntedWeaponAdapter` | Передача атаки оружию и использование оружия как противника |

Для барьера отдельно проверила нулевой урон и значения меньше, равные и больше
его прочности. Например, при прочности 30 удар 29 полностью поглощается,
удар 30 исчерпывает барьер, а после удара 31 проходит 1 единица урона.
В тесте всей цепочки проверяется прохождение запроса через каждый обработчик:
100 урона → броня 25% оставляет 75 → барьер поглощает 30 → остаётся 45.

## Моки и работа с файлами

В тестах Proxy я подменила хранилище через `create_autospec(HeroRepository)`.
Сам Proxy остаётся настоящим. Проверка `assert_called_once_with()` позволяет
убедиться, что повторный поиск берёт героя из кэша и не читает хранилище заново.

Для уклонения использовала `patch("combat.Dice")`, чтобы проверить оба исхода
без зависимости от случайного броска. Перед каждым новым тестом задаётся seed,
а после него восстанавливается предыдущее состояние генератора.

В `TestFileHeroRepository` проверила сохранение и загрузку через настоящий JSON-файл.
Для загрузки создаётся новый репозиторий. Сравниваются характеристики героя,
снаряжение, зачарования, инвентарь и достижения. Каждый тест использует временную
папку `tmp_path`, поэтому игровые сохранения остаются отдельно.

Также добавила сквозной тест: игра запускается отдельным процессом, создаётся
герой, проходит бой, затем игра сохраняется, перезапускается и загружает героя.

## Как запустить

Нужен Python 3.12 или новее. Из корня проекта установить зависимости:

```console
python -m pip install -r lab5/requirements-dev.txt
```

Запустить все тесты одной командой:

```console
python -m pytest -v
```

В PyCharm можно открыть `lab5/run_tests.py` и нажать **Run**.
Саму игру можно запустить через `lab4/main.py`.

Чтобы запустить только новые тесты: `python -m pytest lab5/tests -v`.
Для отдельных групп используются метки `-m unit`, `-m integration`, `-m e2e`
и `-m smoke`. Эти метки назначены новым тестам.
