# Лабораторная №5 — автоматизированное тестирование

Николь Корбут, БИВТ-25-4-4. Python 3.12+, pytest и unittest.mock.

Пятая лабораторная находится в отдельной папке `lab5`. Проверяется настоящий
код игры из `lab4`: новые копии игры не создаются. Это продолжение лабораторных
3 и 4, как требуется в задании. Сохранения пользователя тесты не затрагивают.

## Запуск в PyCharm

Откройте общий проект `tech-prog-2026`. В папке `lab5` нажмите правой кнопкой
по `run_tests.py` → **Run 'run_tests'**. В конце должно быть `passed`, код выхода 0.
Интерпретатор — `.venv` в корне проекта. Игра по-прежнему запускается через `lab4/main.py`.
Конфигурации XML для запуска не нужны.

Первичная установка из терминала в корне проекта:

```console
python -m pip install -r lab5/requirements-dev.txt
```

Все новые тесты и 36 прежних проверок игры запускаются одной командой из корня:

```console
python -m pytest -v
```

Только пятая лабораторная: `python -m pytest lab5/tests -v`.
Отдельный класс: `python -m pytest lab5/tests/test_structural.py::TestCachingHeroRepository -v`.
Модульные: `python -m pytest -m unit -v`.
Интеграционные: `python -m pytest -m integration -v`.
Сквозные: `python -m pytest -m e2e -v`. Быстрая проверка запуска: `python -m pytest -m smoke -v`.
Из папки `lab5` все проверки можно запустить командой `python run_tests.py`.

## Изоляция и ожидаемые результаты

Числа для проверок получены из правил игры. Например: 100 урона, броня 25%,
барьер 30 → броня оставляет 75, барьер поглощает 30, проходит 45.
Если барьер применить первым: (100 − 30) × 0.75 = 52.5, округление даёт 53.
Ожидания не вычисляются вызовом тестируемого обработчика.

Общий Dice получает фиксированный seed перед каждым новым тестом;
после теста его предыдущее состояние восстанавливается. Подмены действуют
только внутри `with patch`. Файловые сценарии используют отдельные `tmp_path`.
В Proxy-тестах подменено хранилище, сам Proxy настоящий. В файловых тестах
репозиторий, сериализация и ФС настоящие; отдельный тест моделирует сбой `os.replace`.

Метки unit/integration/e2e применяются к новым тестам. Старые 36 unittest-тестов
включены в полный запуск как регрессия и сохраняют прежнюю структуру без меток.
Успешный прогон подтверждает проверенные сценарии, но не доказывает отсутствие всех ошибок.
Точное число проверок и локальный результат записаны в `verification.txt`.
